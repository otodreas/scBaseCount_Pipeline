\section*{Introduction}
The scale and heterogenaiety of single-cell RNA sequencing (scRNA-seq) datasets are rapidly expanding~\parencite{lueckenBenchmarkingAtlaslevelData2022,muellerBuildingOptimizedSinglecell2026}. Multiple scientific efforts have been undertaken in integrating collections of scRNA-seq datasets with improvements in sequencing technology and analysis methods~\parencite{rozenblatt-rosenHumanCellAtlas2017}. The Sequence Read Archive (SRA) is the largest repository of scRNA-seq data~\parencite{youngblutScBaseCountAIAgentcurated2025} and is complex by nature because a wide array of laboratories and organizations might contribute to it~\parencite{leinonenSequenceReadArchive2011}. The Gene Expression Omnibus (GEO) is also community-derived while enforcing reporting standards relating to data and metadata~\parencite{cloughGeneExpressionOmnibus2016}. Other initiatives, such as the Human Cell Atlas~\parencite{rozenblatt-rosenHumanCellAtlas2017} and CZ CELLxGENE Discover~\parencite{czicellscienceprogramCZCELLxGENEDiscover2025}, aim to balance scalability with accommodation for efficient meta-analysis, by combining standardization of cell matrices and extensive metadata with community driven contribution~\parencite{czicellscienceprogramCZCELLxGENEDiscover2025}. The recent development of scBaseCount has attempted to address the need for consistent processing in these aggregated collections of scRNA-seq data by leveraging agentic AI-driven metadata unification to uniformly process scRNA-seq datasets in the resource~\parencite{youngblutScBaseCountAIAgentcurated2025}.

\section*{Materials and methods}
Building an integrated lung atlas using scBaseCount data required developing robust single-cell workflows in Python using Scanpy~\parencite{wolfSCANPYLargescaleSinglecell2018}. Observability was enforced through extensive logging configured with the Python logger.
\subsection*{Data aquisition}
scBaseCount data, which includes expression matrices, are hosted on Google Cloud Platform in Google Cloud Storage (GCS) buckets~\parencite{youngblutScBaseCountAIAgentcurated2025}. We used the \texttt{2026-01-12} snapshot of scBaseCount. Before downloading any matrices, we identified a subset of the available matrices that represented lung tissue. We accomplished this by filtering scBaseCount's tissue metadata using a regular expression containing lung-like words, such as ``lung,'' ``pulmonary,'' ``alveolus/i/ar.'' The datasets whose metadata passed that filter were sequentially fetched from GCS and their MD5 hashes computed on disk. Due to the extensive cumulative size of the datasets, the datasets themselves, along with the newly computed hashes, were uploaded to an internally owned and maintained Cloudflare R2 bucket, serving as a production mirror of scBaseCount, allowing for local files to be removed from disk. We re-computed the hash whenever a dataset was downloaded from R2 for local computing to ensure file provenance to scBaseCount.
\subsection*{Atlas construction \& quality control}
To make the aquired individual datasets usable as a single atlas-scale \texttt{h5ad} file, a pipeline was built to sequentially download scBaseCount datasets from the R2 mirror, filter them by performing quality control operations, determining if what remained of the filtered datasets was sufficient for inclusion in the atlas, aligning the datasets to a fixed gene axis, and concatenatenating the datasets to one in-memory atlas. The concatenated atlas was written to disk on pipeline completion.

After dataset download from R2 and before filtering, the dataset's MD5 hash was computed and compared to the MD5 hash stored as metadata alongside the R2 object, the latter having been computed upon upload. Identity between the two hashes was enforced.

Next, cells and genes were filtered based on tunable parameters. The first step of was to filter cells expressing fewer than 200 genes. All genes were maintained, regardless of cell count. Genes were flagged as likely mitochondrial, ribosomal, and hemoglobin genes by applying regular expressions to the gene names. Cells expressing 20\% mitochondrial genes or more were dropped, and cells expressing 50\% ribosomal genes or more were dropped. Cells were not filtered on hemoglobin genes. Following these filters, a cutoff on number of remaining cells and percentage of cells remaining relative to the initial number of cells in the dataset was applied. Datasets were not included in the atlas if they had fewer than 100 cells remaining or if fewer than 50\% of cells remained in the dataset following filtering. Every mentioned threshold was configured as a tunable parameter. To ensure that the values we settled on were well calibrated, the number of cells dropped by each filter was recorded per dataset, allowing the filtering pipeline to be rerun with different filtering parameters. Doublet detection was not applied. Filtering parameters were chosen based on recommendataions proposed by~\textcite{lueckenCurrentBestPractices2019} and enriched with the ribosomal and hemoglobin filters. \subsection*{Embedding \& batch correction}
We developed a method to embed and cluster the atlas using the CELLxGENE \texttt{cell_type} key present in some datasets~\parencite{czicellscienceprogramCZCELLxGENEDiscover2025}. First, we normalized gene counts per cell so that each cell had the same total gene count. Then, we logarithmized the data matrix by the natural logarithm, selected the top 2,000 highly variable genes (HVG) stratified by BioSample---a number in the range of recommended HVGs by~\textcite{lueckenCurrentBestPractices2019}---and \textit{z}-scaled the expression of each gene. We then applied principal component analysis (PCA) to compute the minimum of the PCs accounting for (TODO: report \%) and the first 50 PCs. We then recorded how many of those 50 PCs explained at least 50\% of the cumulative variance explained by the PCs. The processing steps through PCA were applied using Scanpy~\parencite{wolfSCANPYLargescaleSinglecell2018}. We then applied batch correction with BioProject set as the batch variable by Harmonizing the PCs~\parencite{korsunskyFastSensitiveAccurate2019}. To ensure that batch correction was successful, we applied the scIB benchmarking pipeline on the Harmonized PCs, as well as the PCs Harmonized by SRA experiment accession~\parencite{lueckenBenchmarkingAtlaslevelData2022}.

To vizualise and cluster the data, we computed the nearest neighbors distance matrix and a neighborhood graph of observations and applied Scanpy's reproducible, single threaded UMAP dimensionality reduction implementation~\parencite{mcinnesUMAPUniformManifold2018}. The neighborhood graph was clustered using the Leiden algorithm~\parencite{traagLouvainLeidenGuaranteeing2019}.
